# 抖音视频字幕解析、Windows 绿色版与离线更新设计

> 历史基线：本文记录 v1.1.0 首版设计。v1.2.0 的本地 `small/medium` 模型选择、简体与基础标点方案以 [`2026-08-25-local-asr-model-selection-design.md`](./2026-08-25-local-asr-model-selection-design.md) 为准。

## 背景

当前仓库已经具备 FastAPI 本地服务、抖音扫码登录、单视频解析、清晰度选择、视频预览、异步下载进度和最近下载任务。此次扩展在保留既有下载能力的基础上，增加单视频语音转文案，并交付可解压运行的 Windows 10 绿色版及离线更新包。

“字幕/文案”在本文中只表示视频声音的 ASR 转写结果，不表示抖音发布描述，也不包含画面 OCR。

## 目标

- Web 页面提供“视频下载”和“字幕解析”两个 Tab，共用服务状态及抖音登录状态。
- 字幕解析支持粘贴单条抖音视频链接，展示处理进度、完整文案和带时间范围的分段。
- 支持一键复制全文和下载 UTF-8 TXT 文案。
- 识别结果持久化，程序重启和版本更新后仍可查看。
- 交付 Windows 10 x64 绿色目录，解压后双击 EXE 即可运行，不要求安装 Python、FFmpeg 或模型。
- 后续版本通过“更新包 ZIP + 一键更新.bat”离线更新，保留 Cookie、模型、浏览器、下载文件和转写结果。

## 非目标

- 不处理图集、直播、用户主页批量采集或批量转写。
- 不识别画面中的文字，不生成 OCR 结果。
- 首版不启用 GTX 1050 Ti GPU 推理，不打包 CUDA 或 cuDNN。
- 不实现联网自动检查更新、云端账户、云同步或远程 API。
- 不在首版提供模型切换、并发数设置或高级 Whisper 参数面板。

## 技术方案

### 总体架构

继续使用现有 Python + FastAPI + 静态 HTML 架构。新增的字幕任务复用当前抖音解析和下载直链能力，通过独立的任务管理器在后台线程中运行。ASR 使用 `faster-whisper-small` 多语言 CTranslate2 模型，设备固定为 CPU，计算类型为 `int8`。

字幕任务仅允许一个处于运行态。新的请求在已有任务运行时进入队列，以避免 i5-10400F 同时执行多个模型推理导致整机失去响应。视频下载任务保持现有并发行为，不与字幕队列共享状态。

### 字幕数据流

1. 前端提交抖音分享链接。
2. 后端读取当前本机 Cookie；没有 Cookie 时返回 401，并引导用户先登录。
3. 后端创建字幕任务并立即返回任务 ID。
4. 后台任务解析视频元数据和下载地址，将视频保存到任务临时目录。
5. 懒加载全局唯一的 `faster-whisper-small` 模型实例。
6. 模型直接读取媒体文件，由 PyAV 解码音频；不调用外部 FFmpeg 可执行文件。
7. 每产生一个真实分段，更新任务的分段数、当前音频时间和总时长。
8. 完成后写入 JSON 清单和 UTF-8 TXT 文案，再删除临时媒体文件。
9. 失败时保留错误状态但删除不完整的临时媒体；用户可以用原链接重新创建任务。

### 持久化格式

字幕结果存放在便携根目录的 `data/transcripts/<task-id>/`：

```text
data/transcripts/<task-id>/
├── manifest.json
└── transcript.txt
```

`manifest.json` 至少保存：任务 ID、原始链接、作品 ID、作品描述、作者昵称、状态、错误、创建/更新时间、音频总时长、已处理时长、真实分段数、完整文案和各分段的开始时间、结束时间及文字。

启动时只从这些清单恢复字幕历史。状态为运行中或排队中的旧任务恢复为“已中断”，不自动重新下载或继续识别。

### API

新增接口：

- `POST /transcription/tasks`：创建字幕任务，请求体包含 `url`。
- `GET /transcription/tasks`：按更新时间倒序返回历史任务摘要。
- `GET /transcription/tasks/{task_id}`：返回状态、进度、全文和分段。
- `GET /transcription/tasks/{task_id}/text`：下载 UTF-8 TXT。

现有下载、预览、登录和健康检查 API 保持兼容。健康检查增加 ASR 模型是否存在、字幕队列是否忙碌和应用版本字段，但保留现有字段。

错误响应继续使用 FastAPI 的 `detail` 文本。创建请求缺少链接时由参数校验拒绝；链接无效或内容为图集时，异步任务进入失败态并保存明确原因；未登录返回 401；任务不存在返回 404；未完成时下载文案返回 409；模型缺失或损坏在任务状态中返回明确错误，不伪造空文案。

### Web 界面

保留当前暖色纸张质感和响应式布局，重组为共享顶部区域加业务 Tab：

- 共享区域：产品标题、服务状态、Cookie 状态、登录和退出。
- “视频下载”Tab：完整保留当前链接解析、清晰度、预览、下载进度及最近任务。
- “字幕解析”Tab：链接输入、开始识别按钮、当前阶段、进度条、音频时间、结果区和最近字幕任务。

结果区显示作品信息、全文和实际分段。提供“复制全文”和“下载 TXT”；复制失败时显示可理解的错误。页面刷新后从历史接口恢复任务，不把完整文案仅存于 `localStorage`。

键盘和可访问性要求：Tab 使用按钮语义和 `aria-selected`，输入框有可见标签，加载按钮禁用重复提交，状态变化使用 `aria-live`。

## Windows 绿色版

### 目录结构

发布包采用 PyInstaller `onedir`，目录结构固定为：

```text
抖音视频工具/
├── 抖音视频工具.exe
├── _internal/                  # Python 与 Windows 原生运行时
├── browsers/                   # 随包附带的 Playwright Chromium
├── models/
│   └── faster-whisper-small/   # 平台无关的 CTranslate2 模型
├── web/
│   └── index.html
├── data/                       # 首次运行创建，不随更新覆盖
├── downloads/                  # 首次下载创建，不随更新覆盖
├── 一键更新.bat
├── updater.ps1
└── 版本说明.txt
```

运行时根目录以冻结后的 EXE 所在目录为准，源码运行时仍以仓库根目录为准。配置、Cookie、字幕结果和下载目录都使用运行时根目录，不能写进 PyInstaller 临时目录。

EXE 启动本进程内的 FastAPI 服务，等待健康检查成功后打开系统默认浏览器访问本地页面。首版保留控制台窗口，用户关闭窗口即可退出服务；重复启动时检测已有健康服务并只打开页面，不抢占端口。

扫码登录固定使用绿色目录中的 Playwright Chromium。发布包不得依赖目标电脑预装 Chrome、Python、Visual C++ 开发环境或系统 FFmpeg。

### Windows 构建

PyInstaller 不能在当前 macOS 环境直接生成 Windows 可执行文件，因此仓库增加 Windows 构建脚本和 GitHub Actions `windows-latest` 工作流。工作流执行测试、安装固定版本依赖、下载 Playwright Chromium 和指定版本的 small 模型、构建 onedir、执行包结构检查并上传 ZIP artifact。

完整绿色包必须在真实 Windows 10 x64 或等效 Windows CI 环境完成启动、健康检查、页面加载和模型初始化冒烟验证后才能作为交付物。

## 离线更新

### 更新包格式

普通更新包不包含 `models/`、`browsers/`、`data/` 或 `downloads/`，结构为：

```text
更新包-vX.Y.Z.zip
├── update-manifest.json
└── payload/
    ├── 抖音视频工具.exe
    ├── _internal/
    ├── web/
    └── 版本说明.txt
```

`update-manifest.json` 保存目标版本、最低可升级版本、负载内每个文件的相对路径、字节数和 SHA-256。若未来必须更新模型或 Chromium，发布单独标记为“完整更新”的包，显式携带对应目录；普通更新永不删除这些大文件。

### 一键更新流程

同事将更新 ZIP 放在程序根目录，双击 `一键更新.bat`。BAT 内容保持纯 ASCII，只负责调用同目录的 `updater.ps1`，避免 Win10 默认代码页误读中文脚本路径；更新逻辑由 Windows 自带 PowerShell 执行：

1. 确认根目录内只有一个匹配的更新 ZIP，或选择版本号最高的一个。
2. 结束正在运行的 `抖音视频工具.exe`。
3. 解压到同盘临时目录，读取清单并逐文件校验大小和 SHA-256。
4. 校验目标版本高于当前版本，且当前版本满足最低升级版本。
5. 将旧的 EXE、`_internal/`、`web/` 和版本说明移动到单个回滚目录。
6. 将新负载移动到正式位置。
7. 再次校验正式位置文件；失败则删除不完整的新核心并恢复回滚目录。
8. 成功后保留最近一次回滚目录，写入更新日志并重新启动 EXE。

更新过程不得读取、复制到外部位置或覆盖 `config.json`、`data/`、`downloads/`、`models/`、`browsers/`。批处理窗口必须显示成功或具体失败原因，并等待用户按键后关闭。

## 版本与依赖

- 应用版本在单一 Python 模块中定义，并由健康检查、版本文件、构建脚本和更新清单读取。
- Python、FastAPI、Uvicorn、Playwright、faster-whisper、CTranslate2、PyAV 和 PyInstaller 使用锁定版本的 Windows 构建依赖文件。
- 模型固定到 Hugging Face 仓库的明确 revision，构建时记录 revision，不使用随时间变化的隐式 latest。
- 首版更新协议版本为 `1`；不为尚未出现的协议提前增加兼容层。

## 测试与验收

### 自动化测试

- 字幕任务的排队、状态转换、单并发、真实分段进度和失败清理。
- 模型懒加载与固定 CPU `int8` 参数。
- 字幕清单写入、重启恢复、运行中任务恢复为已中断、TXT 下载。
- API 的 400、401、404、409 和成功响应。
- 运行时根目录在源码模式与 PyInstaller 模式下的解析。
- 更新清单生成、路径穿越拒绝、哈希失败拒绝、数据目录排除和回滚。
- Web 页面包含两个可访问 Tab、字幕输入、进度、复制、TXT 下载和历史恢复逻辑。
- Windows 构建产物包含 EXE、模型、Chromium、Web 页面和更新脚本，不包含本机 Cookie 或既有数据。

### 人工验收

在目标或等效 Windows 10 x64 环境执行：

1. 全新解压后双击 EXE，服务启动且默认浏览器打开。
2. 扫码登录成功，关闭并重启后仍保持 Cookie。
3. 视频下载 Tab 可解析、预览并下载一个视频。
4. 字幕解析 Tab 可将一个包含中文语音的视频转成非空文案，进度和实际分段数变化正确。
5. 复制全文和 TXT 下载内容一致，中文无乱码。
6. 程序重启后仍能看到已完成文案。
7. 放入普通更新包并双击 BAT，程序升级成功且 Cookie、模型、浏览器、下载文件和字幕记录均保留。
8. 使用被篡改的更新包时更新被拒绝，旧版本仍能运行。

## 已知约束

- 抖音页面、接口、Cookie 或风控变化可能导致解析失败；错误必须明确暴露，不能把空响应当成成功。
- CPU 识别速度取决于视频时长和 10400F 的可用负载；界面不承诺固定耗时。
- Windows EXE 必须在 Windows 构建并在 Windows 10 上验证；macOS 本地只能完成源码测试、静态检查和更新逻辑的跨平台单元测试。
